Sources read for this note (codeload tarballs, October 2026): `JeffersonLab/libsbsdig@mcpass4`
(`src/g4sbs_data.{h,cxx}`, `g4sbs_tree.cxx`, `SBSDigGEMSimDig.cxx`, `SBSDigGEMPlane.*`, `SBSDigAuxi.cxx`,

(`SBSSimDecoder.cxx`, `SBSSimDataDecoder.cxx`, `SBSGEMModule.cxx`, `SBSGenericDetector.cxx`) and

## 1. What the digitized tree contains

libsbsdig appends `*.dighit.*` branches to the g4sbs tree `T` (`g4sbs_tree.cxx` l.108–137, types in `g4sbs_data.h`).
All are `std::vector<int>` with one entry per **sample** (not per channel).

| branch prefix | type | branches | content |
|---|---|---|---|
| `Earm.BBGEM.dighit` | `DigGEMData_t` | `nstrips, module, strip, adc, samp` | one entry per (strip, time sample); `nstrips` counts entries (6 per strip) |
| `Earm.BBSH.dighit`, `Earm.BBPS.dighit` | `DigSampCalData_t` | `nchan, chan, adc, samp, tdc` | one entry per FADC sample (`samp`=0..N−1, `tdc`=−1000000) |
| `Harm.HCal.dighit` | `DigSampCalData_t` | same | FADC samples as above, plus TDC entries with `samp = adc = −1000000`, `tdc` = F1-like word |

**GEM** (`SBSDigGEMSimDig::CheckOut`, l.1385–1490):
* `module` is the libsbsdig **plane** index *p* (`GEMPlanes[i]`), *p* = 2·*m* + *axis*, *m* = module in config order,
  *axis* 0 = X/U (`RO_angle` −30° or 0°), 1 = Y/V (+30° or 90°). For the GEn/SIDIS BigBite configs
  (`db_gen_conf_8gemmodules_GEN2/3/4.dat`, identical GEM blocks): 16 planes, *m* = 0–3 UV layers 1–4 (3840 + 3840 strips),
  *m* = 4–7 the four X/Y modules of layer 5 at x = −0.768, −0.256, 0.256, 0.768 m (1280 X + 1536 Y strips).
* `strip` = strip index on the plane; strip 0 at −nstrips·0.4 mm/2 along the rotated axis
  (`AvaModel_2`: `iL = (xs·1e-3 + dX/2)/fStripPitch`, pitch 0.4 mm, `xs = x cos(−RO) − y sin(−RO)`).
* `adc` = sample *k* (`samp` = 0..5, `fNSamples` = 6) **including** a common-mode baseline `commonmode_array_bbgem`
  (1500 in the GEN configs) plus Gaussian noise σ = 20, saturated at 2¹² (`fADCbits` = 12).
* A strip is written if `ΣADC − 6·baseline > ZsupThr_bbgem` (240): emulated online zero suppression.
* **No signal flag.** `Earm.BBGEM.dighit_sig` is commented out (`g4sbs_tree.cxx` l.132, `CheckOut` l.1452). The per-hit
  `source` (0 signal file, 1 background from `SBSDigBkgdGen`) exists internally (`SBSDigGEMDet::gemhit`, `Digitize` l.1242) but is
  not written. Background GEM hits are generated by `SBSDigBkgdGen` from histograms and never appear in `Earm.BBGEM.hit`;
  hence every `Earm.BBGEM.hit` entry belongs to the signal event (primary + its secondaries).

**PMT** (`SBSDigPMTSignal::Digitize`, l.483–600, 840–870): only channels with N_pe > 0 are written; `adc` = FADC sample
(charge·1e15/ADCconv + Gaus(ped, σ_ped), clipped at 4095) — the pedestal is included, as in real FADC250 raw data.
BBSH/BBPS: samples only. HCal: samples + TDC entries.

## 2. How SBSSimDecoder (mcpass4) maps them (MC replay)

`SBSSimDecoder::LoadDetector` (l.767–1240) + `ReadDetectorDB` (l.2025–2300), with `DB_MC/` and the sim crate map
`db_sbssim_cratemap.dat` (sim encoders: models −250/−3561/... ; GEMs in fake crate 19, slots 0–18).

* **GEM**: `APVnum(det, mod=dighit.module, h_chan=strip)`: `chan = strip % 128`, APV *n* = strip/128 = *n*-th chanmap row of that
  axis in DB order; `fInvGEMDetMap[2·m+axis]` with *m* = index in `bb.gem.modules`. Word = `strip%128 << 13 | adc`.
  `SBSGEMModule` in MC mode (`is_mc=1`, `apvmap=3`) uses `strip = rawstrip + 128·pos` (l.5527) and subtracts
  `pedu/pedv = 1500`. Consistent only if the *n*-th APV of each axis has `pos = n`: **checked**, true for every module/axis of
  `DB_MC/20220106/db_bb.gem.dat` and `DB_MC/db_bb.gem_8modules.dat` (30/30/…/10/12 APVs). ⇒ libsbsdig strip index ≡ SBS-offline MC strip index.
* **BBSH**: `row = c%27, col = c/27, l = row·7+col`; **BBPS**: `row = c%26, col = c/26, l = row·2+col`; **HCal**:
  `col = c%12, row = c/12, col = 11−col, l = row·12+col`; then `ChanToROC(l)` → (crate, slot, chan) from detmap/chanmap
  (`chan_offset` 0 for sh/ps, 1 for HCal ⇔ `start_chanmap`). HCal TDC at `ChanToROC(l+288)`.

## 3. Inverse mapping to the REAL readout (what `sbsdig2evio` writes)

**GEM strip → (crate, slot, fiber, adc, apv_chan).** Real decode (SBS-offline `MPDModule` + `SBSGEMModule::GetStripNumber`,
gemfilter `geom::ApvMap`): chanmap row `crate slot mpd_id gem_id adc_id i2c pos invert axis`, VTP-era fiber = `mpd_id`;
`strip = APVMAP[apvmap][chan]; strip += (127−2·strip)·invert; strip += 128·pos`. `sbsdig2evio` builds the inverse table by
running that forward map over all 128 channels of every APV (as `track/Toy.cxx`), then for each dighit strip:
sim plane *p* → DB module `module_map[p/2]` (default identity), axis *p*%2, same strip index → readout address.
Real DB `DB/20220701/db_bb.gem.dat` at 2023-06-01 (GEn-II layout, after the 2023-01-24 cable swap-back): 8 modules,
41 984 strips, **all mapped, no duplicates**, 328 APVs on 23 fibers, all in ROC 20, slot 11 (VTP). Strip counts per module/axis equal
the libsbsdig GEN config (checked by `make_sim_db.py --sbsdig-db`).
Samples: `mpd = clamp(adc − 1500, −4096, 4095)` (signed 13 bit, online-pedestal/CM-subtracted format), 6 samples; frame header
`ENABLE_CM = 1`; hits ordered by APV channel; block layout of `codec::synth::write_block` (VTP-era, one block per slot).

**PMT channel → FADC250 (crate, slot, chan).** sim chan → logical element *l* (rules of §2) → `CaloGeometry::blocks[l]`
(gemfilter port of `SBSGenericDetector`: `element = chanmap[k] − start_chanmap` over the detmap channel list) → (crate, slot, chan).
Cross-check: a Python port of the detmap/chanmap rule gives the same (crate, slot, chan) as gemfilter for all 189 BBSH, 52 BBPS
and 288 HCal elements of the real DB at 2023-06-01. Real readout: BBSH + BBPS in ROC 6 (slots 3–10, 13–20), HCal in ROC 28
(16 slots) and ROC 29 (slots 19, 20); FADC bank tag 3 (`db_cratemap.dat` bank column). Samples written unchanged
(window raw data, type 4, `seeds::encodeFadc250Block`).

**Not written:** HCal / hodoscope / GRINCH TDCs, GRINCH and hodoscope ADCs, SBS-arm GEMs (not digitized in mcpass4 for SIDIS).
The trigger bank (event numbers, 1 µs + 250 ns·N timestamps, event types 1–3) and MPD/FADC trigger-time words are SYNTHETIC
placeholders — there is no TS in simulation.

## 4. Geometry: why a hybrid DB is needed (`make_sim_db.py`)

The converted file uses real electronics addresses but **simulation strip/element indices**. Interpreting them with the real
geometry is wrong: real BB GEM UV modules have `uangle = 150°` vs 330° (−30°) in DB_MC/libsbsdig (U mirrored), sizes 1.50 × 0.40 m
vs 1.536 × 0.4096 m, real alignment offsets; real BBSH/BBPS z = 1.902/1.696 m vs 1.957/1.750 m in DB_MC. `make_sim_db.py` writes a
flat DB directory: every DB_MC file, the real `db_cratemap.dat`, and for `bb.gem`, `bb.sh`, `bb.ps`, `sbs.hcal` the DB_MC values with
the decode-map keys (`m*.chanmap`, `m*.apvmap`; `detmap`, `chanmap`, `start_chanmap`, `nchan`) replaced by the real ones resolved at
`--date`, plus `is_mc=0, onlinezerosuppress=1, pedestalmode=0, pedsub_online=1, m*.pedu=m*.pedv=0`.
Checked: the GEM strip→readout map and the calorimeter element→readout map from the hybrid DB are identical to the real DB's.
Consequence to keep in mind: on U planes the APV/fiber occupancy pattern is the real one for *index* s, i.e. mirrored with respect to
where the real detector would see the same track; data volume per event is unaffected.

## 5. Truth sidecar

`<out>.truth.tsv`, one line per dighit GEM strip:
`event crate slot fiber adc chan module axis strip sig maxadc entry` (event = CODA event number, module = DB module index,
crate = −1 if the strip had no readout address). Key for gemfilter metrics: (event, crate, fiber, adc, chan).
`sig` source (header line `truth_source=`):
1. `dighit_sig_branch`: `Earm.BBGEM.dighit.sig` (per sample; strip is signal if any sample flag ≠ 0). Requires
   `tools/sbsdig2evio/libsbsdig_gem_sigflag.patch` (apply in the libsbsdig tree with `patch -p1`): the plane keeps a per-strip
   flag set in `AvaModel(_2)` when the current hit has `source == 0` and deposits charge on that strip.
2. `g4sbs_hit_geometry` (stock mcpass4): every `Earm.BBGEM.hit` with edep > 0 is projected onto both planes of its module with the
   libsbsdig geometry (`SBSDigAuxi::UnfoldData` module search, `AvaModel_2` rotation and strip formula); strips in
   [s(in), s(out)] ± `--hit-margin` (default 4) are signal. Approximate: background strips in that window count as signal, signal
   charge spread beyond the margin counts as background.
3. none: `sig = −1`.

## 6. Tools and test

```
python3 tools/sbsdig2evio/sbsdig_extract.py -i digitized.root -o run.sdg [--truth auto|sig|hits|none] \
        [--sbsdig-db libsbsdig/db/db_gen_conf_8gemmodules_GEN2.dat] [--hit-margin 4]
python3 tools/sbsdig2evio/make_sim_db.py --mc-db SBS-replay/DB_MC --real-db SBS-replay/DB \
        --sbsdig-db libsbsdig/db/db_gen_conf_8gemmodules_GEN2.dat --date "2023-06-01 00:00:00" -o simdb
build/tools/sbsdig2evio/sbsdig2evio -i run.sdg -o run.evio --db simdb [--block-level 5] [--gem-baseline 1500]
build/tools/sbsdig2evio/sbsdig2evio_verify -i run.evio --sdg run.sdg --db simdb --truth run.evio.truth.tsv
build/bin/gemfilter_file -i run.evio -o run_filt.evio --csv m.csv -p gem:config/sidis_bb_sim_road.cfg
```
Design choice: stage 1 in Python/uproot (no ROOT installation, keeps the "no ROOT in gemfilter" contract, reads both
`std::vector` and counted-array branches), stage 2 in C++ so that the EVIO is written by the same codec/FADC code gemfilter decodes
with. `.sdg` format: `tools/sbsdig2evio/sdg_format.h`.

CTest `converter.roundtrip` (skipped with exit 77 if uproot/awkward are missing): SYNTHETIC tree with the exact branch names and
per-sample layout (23 events, ≈10 k strips, ≈430 FADC channels incl. saturated/negative GEM samples and HCal TDC entries) →
`.sdg` → EVIO with the real DB snapshot → decode with the production decoders and **forward** maps: every strip and all 6 samples,
every FADC channel, all samples and sums identical, no extra/duplicate channels, event numbers continuous, 3 control events; branch
truth and hit-geometry truth agree; 7-event partial-block run; `gemfilter_file --list-banks` sees the MPD banks.

UNVERIFIED (needs real digitized files / ROOT): reading of genuine `std::vector<int>` branches (uproot reads them as the same
jagged arrays); the libsbsdig patch has not been compiled; the hybrid-DB decoder flags have not been tried in an SBS-offline replay
(test: SBSSimDecoder replay of the ROOT file vs real-decoder replay of the EVIO must give identical strip lists); the real BB GEM
readout for SIDIS is assumed equal to GEn-II (no SIDIS DB exists).
